# Arrow Puzzle

[English version](README.md)

Arrow Puzzle — минималистичная головоломка для ПК, в которой нужно распутать
поле из стрелок. Игра написана на C++20 с использованием raylib и пока
ориентирована на Windows.

В версии **0.3.0** доступны поля 20 x 20, 40 x 40, 80 x 80 и экспериментальное
160 x 160, тёмная и светлая темы игрового поля, отключаемые звуки и
анимированные финальные экраны.
Настройки и незавершённая партия сохраняются рядом с исполняемым файлом.

## Правила игры

Каждая стрелка — это ломаная линия, занимающая клетки сетки. Остриё задаёт
направление, в котором всё тело движется по одной клетке, подобно змейке из
классической игры Snake.

Кликните по стрелке, чтобы запустить её. Запущенная стрелка подсвечивается
синим, начинает движение медленно и плавно ускоряется, подобно маленькой
ракете, без ограничения максимальной скорости. Для удаления она должна
полностью покинуть поле. Столкновение с неподвижной стрелкой или собственным
телом отнимает одну из трёх жизней: ошибочная стрелка становится красной,
возвращается на исходное место и остаётся красной в состоянии покоя. Цель —
полностью освободить поле.

Столкновение стрелки с самой собой проверяется в динамике, а не по статичному
снимку. Голова может войти в клетку, которую хвост освобождает на том же шаге,
но не может пройти сквозь любую другую часть собственного тела.

Одновременно могут двигаться несколько стрелок. Если две движущиеся стрелки
соприкасаются, игрок теряет одну жизнь, но обе стрелки проходят друг сквозь
друга и продолжают движение вместо возврата. Перед полусекундной паузой обе
становятся красными и сохраняют этот цвет до конца полёта, поэтому момент
контакта и потеря жизни заметны и после возобновления движения. Правильный
выбор момента запуска становится частью головоломки.

У каждой стрелки собственные скорость и часы движения. Кадр рассчитывается
хронологически по всем пересечённым стрелками границам клеток, поэтому даже
стрелка, пролетающая несколько клеток за один кадр, не может проскочить сквозь
препятствие. Отрисовка при этом движется непрерывно по пикселям. Прямые углы
не деформируются: линия нарастает у головы и исчезает у хвоста без
диагонального растягивания. Бюджет событий на кадр сохраняет отзывчивость на
очень больших полях и при необычно высокой скорости: необработанное время
переносится дальше, а проверки коллизий никогда не пропускаются. Новый клик
получает временную отметку после уже накопленной очереди симуляции, поэтому
никакой старый долг не может передать новой стрелке чужую скорость.

| Ввод | Действие |
| --- | --- |
| Левая кнопка мыши | Запустить неподвижную стрелку |
| Колесо мыши | Изменить масштаб относительно указателя |
| Средняя кнопка мыши + перетаскивание | Переместить поле |
| Стрелки вверх / вниз | Переместить текущий выбор в меню |
| Enter | Активировать выбранный пункт меню |

| Стрелка назад слева вверху | Сохранить незавершённую партию и вернуться в меню |
| Кнопка динамика в верхней панели | Включить или выключить звук |
| F11 или левый Alt+Enter | Переключить полноэкранный режим |
| Escape | Выйти из полноэкранного режима, вернуться в меню или закрыть главное меню |

после столкновения и обратного движения ввод временно блокируется.

## Меню, настройки и сохранения

В меню New game доступны четыре размера:

- Simple: 20 x 20
- Middle: 40 x 40
- Hard: 80 x 80
- Very Hard: 160 x 160

Very Hard пока экспериментальный. Как и меньшие режимы, он параллельно
обрабатывает восемь вариантов и выбирает клубок с наибольшей оценкой.
Интерфейс остаётся отзывчивым и показывает анимированный индикатор, пока
варианты сравниваются.

В Settings можно запретить динамические самопроходы во вновь генерируемых
уровнях и отключить потерю жизни при столкновениях между летящими стрелками.
Изменение настроек не переписывает геометрию уже сохранённой партии.
Неподвижные препятствия работают в обоих режимах. Изменения сразу записываются
в `settings.txt`. Без самопроходов генерация становится строже:
экспериментальный режим Very Hard может отклонить seed и предложить повторную
попытку вместо подстановки более простого поля.

**Crosshair guides** выделяет открытые точки в строке и столбце, ближайших к
курсору. **Sounds** включает встроенные звуковые эффекты; кнопка динамика в
верхней панели меняет ту же настройку. Обе опции по умолчанию выключены.
**Board theme** по умолчанию имеет значение Dark и переключается на Light:
меняются игровое поле и верхняя панель, а меню и финальные экраны остаются
тёмными. Эти настройки тоже сохраняются в `settings.txt`; старые файлы
настроек остаются совместимыми.

Наведение мыши выбирает пункт меню. При уходе курсора или пересечении зазора
этот пункт остаётся выбранным. Стрелки перемещают текущий выбор, даже если
курсор неподвижно находится над другой строкой, до следующего движения мыши.

Кнопка со стрелкой назад рядом с названием игры или Escape позволяет перейти
в меню, изменить настройки и вернуться через **Resume game**. После очистки
поля появляется **YOU WON!** с фейерверками, а после потери всех жизней —
**GAME OVER**. Праздничная анимация завершается автоматически, и законченная
партия перестаёт создавать нагрузку в простое.

При возврате в меню или выходе из игры незавершённое поле сохраняется в
`savegame.txt`, если осталась хотя бы одна жизнь. Файл содержит полную
геометрию, признаки оставшихся и ошибочных стрелок и число жизней; seed и
текущая версия генератора для загрузки не нужны. Без корректного сохранения
пункт Resume game неактивен. Оба текстовых файла находятся в каталоге
`ArrowPuzzle.exe`.

## Сборка в Windows

### Требования

- Visual Studio с инструментами MSVC x64 для C++ и Windows SDK
  (проверено с Visual Studio 2022)
- CMake 3.24 или новее
- Ninja
- Git и доступ в интернет при первой конфигурации

Скрипт сборки сначала ищет CMake и Ninja в `PATH`. Если они не найдены, он
проверяет стандартные пути к инструментам, входящим в комплект CLion.
Устанавливать raylib отдельно не нужно: при первой конфигурации CMake скачивает
исходники закреплённой версии raylib 5.5 и собирает библиотеку статически.
Во время сборки шрифт Inter преобразуется в данные C++ и встраивается прямо в
исполняемый файл. Готовая игра не зависит от шрифтов, установленных в Windows,
и не требует отдельного каталога ресурсов.

### Release-сборка одной командой

Выполните из корня репозитория в обычном окне PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
    -File .\tools\build-windows.ps1 `
    -Configuration Release
```

Скрипт конфигурирует и собирает проект, а затем запускает полный набор тестов.
Стресс-тест генератора создаёт 1314 полей и может выполняться несколько минут.

Готовый исполняемый файл:

```text
build\windows-msvc\arrow_puzzle.exe
```

Запуск:

```powershell
& .\build\windows-msvc\arrow_puzzle.exe
```

Для снимков доступны дополнительные служебные переменные:

- `ARROWPUZZLE_DIFFICULTY` выбирает уровень сложности от `1` до `4`
- `ARROWPUZZLE_SCREENSHOT_MENU` снимает главное меню, выбор игры или настройки (`1..3`)
- `ARROWPUZZLE_SCREENSHOT_FRAME` задаёт номер кадра (по умолчанию `30`)
- `ARROWPUZZLE_SCREENSHOT_REMOVE` скрывает первые N стрелок перед снимком
- `ARROWPUZZLE_SCREENSHOT_LAUNCH` запускает стрелку по индексу с нуля
- `ARROWPUZZLE_SCREENSHOT_LAUNCH_2` позже запускает вторую стрелку
- `ARROWPUZZLE_SCREENSHOT_LAUNCH_2_FRAME` задаёт кадр её запуска

Для Debug-сборки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
    -File .\tools\build-windows.ps1 `
    -Configuration Debug
```

### CMake Presets

Из Developer PowerShell, где CMake и Ninja доступны через `PATH`:

```powershell
cmake --preset windows-msvc
cmake --build --preset windows-msvc
ctest --preset windows-msvc
```

### Проверка выбранного диапазона seed

Скрипт позволяет быстро воспроизвести небольшой диапазон уровней:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
    -File .\tools\build-windows.ps1 `
    -Configuration Release `
    -SeedCount 25 `
    -FirstSeed 700
```

Этот пример проверит стандартные seed от 700 до 724, а также небольшой набор
альтернативных конфигураций поля.

## Как работает генератор

Генератор строит лабиринтный гамильтонов цикл, проходящий через каждую клетку,
а затем при помощи динамического программирования разрезает его на стрелки с
широким распределением длин. Разрез принимается только тогда, когда зависимости
на пути выхода сохраняют конструктивный порядок решения.

Выходные лучи и динамические самопроходы кэшируются один раз для каждого
открытого цикла. На больших полях вместо плотных таблиц размером «площадь ×
число стрелок» используется точный диапазонный поиск достижимости и
восстановление решения, а доступные ходы обновляются через обратный граф
зависимостей. Независимые варианты генерируются параллельно и сравниваются в
детерминированном порядке.

Несколько вариантов сравниваются по контактам между разными стрелками,
пространственному перемешиванию, разнообразию направлений, количеству поворотов,
структуре зависимостей и распределению длин. Все четыре режима параллельно
генерируют восемь вариантов, после чего выбирается клубок с наибольшей оценкой.
Внутренний параметр
`GeneratorOptions::candidateAttempts` уже задаёт компромисс между качеством и
временем и позднее может быть вынесен в меню.

Точный динамический самопроход получает дополнительный балл: голова достигает
клетки собственного тела ровно в тот такт симуляции, когда движущийся хвост
освобождает эту клетку. Длинные и сложные варианты получают дополнительный
бонус. Так появляются обманчивые стрелки-нити, но настоящая самоколлизия
по-прежнему запрещена.

Большие прямоугольные S-образные области штрафуются, чтобы поле напоминало
клубок отдельных нитей, а не несколько территориальных змеек.

Генерация выполняется в фоновом потоке. Игра остаётся отзывчивой и показывает
анимированный полупрозрачный индикатор, пока сравниваются варианты. Простой
построчной змейки в качестве аварийного результата больше нет: если корректный
вариант не найден, игра показывает ошибку и позволяет повторить попытку.
Текущий конструктор гамильтонова цикла требует чётных размеров поля.

Автоматические тесты проверяют полное заполнение поля, корректность геометрии,
заданные ограничения длины, конструктивную решаемость, динамическую
самоколлизию и статистическое качество на множестве воспроизводимых seed.

Seed нужен для разработки и воспроизведения тестов, но не является форматом
сохранения. Сохранённая партия содержит полную геометрию стрелок и текущее
состояние игры, поэтому частично разобранный уровень не зависит от версии
генератора и платформы.

## Переносимость

Пока проверяется только сборка для Windows. Ядро использует стандартный C++20,
а raylib является кроссплатформенной библиотекой, поэтому Linux и Android
рассматриваются как будущие цели, но ещё не поддерживаются текущими скриптами
сборки и тестами.
